# 设计：内页风格统一 + 训练负荷（session RPE）

日期：2026-10-28
状态：待作者确认（已经过一次独立审阅，审阅中提出的问题都已解决）
范围：SimpleWorkoutRecorder（React 19 + Vite 7 + Tailwind 3 的 PWA，部署在 Cloudflare Pages，push `main` 即上线）

---

## 1. 为什么做

这是一个只有作者本人在用的健身记录 app，主要在健身房用手机打开。

**问题一：内页简陋，风格跟封面不一致。** 作者认为封面（Rhodes 风格首页）做得不错，但"里面的内页就都……"。审查发现这不是某一页没做好，而是三个根本原因叠在一起：

1. 只有首页专门做了 Rhodes 版本（`HomeView_Rhodes` / `HomeView_Cyber`），其余内页都只有一套 JSX，而且是按早期 Cyber 风格写的：斜体标题、`rounded-full` 胶囊按钮、大圆角、阴影。
2. `App.jsx` 初始化时，只有 localStorage 里存过 `app_style`，才会给 `<html>` 设置 `data-style`。如果从没手动选过风格，React 状态是 Rhodes，但 `index.css` 里所有 `:root[data-style='rhodes']` 规则都不生效。
3. 颜色有两套来源：
   - Tailwind 的 `primary` / `surface` / `border` / `text-*` 写死成暗色主题的值（如 `#D0FD3E`、`#1C1C1E`）
   - 主题切换只改 CSS 变量，而且漏了 `--color-surface-hover`、`--color-primary-dim`
   - 代码里到处有 `text-white`

   结果是在白底主题下，大量白字看不见，还混进了深灰色块和发淡的荧光绿。

**问题二：想知道"这周练了多少"。** 作者想用 session RPE（练完给整场打 1–10 分）乘以时长，得到训练负荷，用来衡量和对比训练量。有氧运动用佳明手表记录，力量训练在这个 app 里记录。作者实际的分析方式是：把 app 的导出文件和佳明的数据一起放到电脑上，交给 AI 综合分析。

## 2. 目标

- 所有内页看起来跟封面属于同一个 app：白底 Clinical 配色 + Rhodes 风格语言。
- 删掉早期遗留的黑底配色、Cyber 风格和风格切换功能，只保留一套。
- 力量训练练完后可以给整场打 RPE，时长自动记录，得出负荷。
- 可以手动记一笔有氧：类型、时间、分钟数、RPE。
- 封面显示本周练了几次、本周负荷和上周对比。
- 导出的数据能让 AI 按时间对上佳明的记录。

## 3. 非目标

- 接入佳明，包括个人 API 和导入 .FIT 文件。已讨论并决定暂不做（见 §9）。
- 多用户、账号、云同步。
- 深色模式。
- 训练记录页记组流程本身的交互改动。只改样式，以及"完成训练"之后的流程。
- AI 教练对话、计划生成等功能。
- 封面以外的图表或趋势分析。

## 4. 反目标（技术上做出来了，但出现这些就算失败）

- **出现任何网络请求或服务器依赖。** app 必须保持 local-first、完全离线可用。
- **新增强制输入步骤。** 打 RPE 必须可以跳过，打分本身只需点一下。有氧录入是可选入口，不能出现在必经路径上。
- **丢失或损坏已有数据。** 现有的 `workout_history`、`workout_plans`、`default_plan_id` 等必须原样可用；旧记录照常显示。
- **封面除了约定的改动之外变了样。** 尤其是封面上 `#D0FD3E` 荧光绿的文字和 DEPLOY 按钮：作者明确说颜色没问题，不能因为统一色彩变量而跟着变色。
- **仍然弹出浏览器原生的 `alert` / `confirm` 对话框。**

## 5. 约束

- 数据只存在 localStorage。现有 key：`workout_history`、`workout_plans`、`default_plan_id`、`active_session`、`user_profile`、`enabled_quote_packs`、`app_theme`、`app_style`。
- PWA 离线，Service Worker 预缓存。
- 主要目标设备是手机竖屏，按 375px 宽度设计。
- 没有测试套件。`npx eslint src` 目前有 18 个既有错误，新代码不能增加错误数。
- push 到 `main` 会自动部署上线，所以要在分支上开发，合并即发布。
- 作者本人的手机上有真实的历史数据，迁移必须兼容：旧记录 `duration: 0`，没有 `type` 字段；localStorage 里可能存着 `app_style: cyber` 或深色主题。

- 只保留一套颜色定义作为唯一来源，Tailwind 的颜色名映射到这套定义，不再出现两套各自为政的值。
- 白底 Clinical 的取值：

  | 用途 | 颜色 |

  | 主色上的文字 | `#1a2e05` |
  | 背景 | `#ffffff` |

- **封面特例：** 封面现在用的 `#D0FD3E`（带 1px 投影）的文字、标签和 DEPLOY 按钮保持原样，单独给它一个颜色名，不跟随主色。
- 清除内页里所有 `text-white`、写死的暗色值，以及没定义的 class（`btn-secondary`、`btn-danger` 在 `index.css` 里根本不存在）。

### 6.3 内页风格语言（已通过草图确认）

以下规则来自作者确认过的结束页、有氧记录页和按钮草图：

- **页眉：** 第一行是等宽小标签 `>_ SECTION`，深绿色，字距拉宽。下面是大写粗体标题（Inter 900），**不用斜体**。需要的话再加一行等宽、灰色的副标题。
- **卡片和面板：** 方角，1px 边框，面板底色，没有阴影。左上角有一个主色的小科技角标（类似 `.card` 现有的角标）。
- **标签：** 等宽、全大写、字距拉宽、灰色、字号很小。
- **数字和数据：** 一律用等宽字体。
- **主按钮：样式 C**（作者从三个方案里选定的）。DEPLOY 的骨架改成白底版：
  - 浅绿底 `#f7fee7`，2px 主色描边，黑字
  - 左边一道 4px 主色竖条
  - 上面一行等宽小标签（如 `SESSION · PUSH`），下面是粗体动作词（如 `SAVE LOG`）
  - 右边一个箭头，右下角切角，和 DEPLOY 的切角形状一样

  每页只有一个的"主要动作"都用这个样式：训练页的 FINISH、结束页的 SAVE LOG、有氧的 SAVE、编辑器的保存、导入等。
- **紧凑版主按钮**（作者看过预览后确认）：同样是浅绿底、绿描边、左边绿条、右下切角，但只有一行居中的等宽大写字，没有小标签和箭头，高度约 38px。用于在一页里重复出现、或者要按很多次的动作。目前只有训练页的 **LOG SET**。
- **次要动作**（返回、取消、跳过）：用文字链接，等宽、大写、灰色，比如 `← BACK TO SESSION`、`SKIP RATING`。不再用胶囊按钮。
- **选择控件**（RPE 1–10、类型选项）：方格。选中的格子填主色，文字用主色上的文字色。
- **输入框：** 方角，1px 边框，白底，数值用等宽字体。
- **图标：** 只用 lucide，不用 emoji（📤 📥 🔧 这些都要换掉）。
- **页面边距：** 所有页面左右留 14–16px，内容不能贴着屏幕边缘。
- **对话框：** 用 app 自己的确认框和提示替换所有 `alert` / `confirm`，目前有 18 处，用 grep 就能找到。
- **语言：** 界面标签用英文。日期用固定的英文格式，如 `OCT 28 · WED`，不要用依赖系统语言的 `toLocaleDateString(undefined)`，作者的手机上它会输出中文。需要解释的地方可以配一句简短的中文，比如 RPE 量表的说明 `1 很轻松 / 5 吃力 / 10 极限`。这一条是我（Claude）定的，作者没有反对。

## 7. 第二部分：训练负荷

### 7.1 概念

- **session RPE：** 1–10 的整数，代表整场的整体吃力程度，不是最后一组有多累。
- **时长：** 单位是分钟。
- **负荷 = RPE × 分钟**，单位是 AU，显示时只显示数字。
- 没有 RPE、或者时长未知（旧记录）的场次，只计入次数，不计入负荷。

### 7.2 数据模型

`workout_history` 继续是一个数组，力量和有氧都存在里面，用 `type` 区分。

**力量记录**，在现有字段上新增：

```
type: 'strength'          // 旧记录没有这个字段，读取时当作 strength
planId, dayId             // 用来判断练的是哪个训练日（见 §6.4.1）
startTime: <epoch ms>     // 来自 session.state.startTime
endTime:   <epoch ms>     // 按下 FINISH 那一刻
duration:  <分钟，整数>    // 默认 endTime - startTime，可在结束页修改
sessionRpe: 1..10 | null  // 跳过打分则为 null
```

**有氧记录：**

```
{ id, type: 'cardio', activity: 'run'|'bike'|'swim'|'row'|'other',
  date, startTime, duration, sessionRpe }
```

负荷是**算出来的，不存储**，避免和 RPE、时长不一致。导出时再算出来写进文件。

**一场训练"发生在什么时候"（Claude 定的）：**
- 统一用一个函数决定：有 `startTime` 就用 `startTime`，没有就用 `date`（旧记录）。日历归到哪一天、封面算哪一周、导出时间，全都用它。
- 新记录的 `date` 写成 `startTime`，这样仍然读 `date` 的旧代码也会把这一场归到开始那天。
- 不用 SAVE LOG 的时间。结束页可以跨越重启，SAVE 可能在训练结束几小时后、甚至第二天才按。

**时间以哪个为准（Claude 定的）：**
- **力量：** 以 `startTime` 为准，它在开始训练时就记下了，是可靠的。如果在结束页改了 TIME，保存时用 `endTime = startTime + duration` 重新算。改 TIME 通常就是因为"忘了按结束"，这时原来记下的 `endTime` 恰恰是错的。
- **有氧：** 表单里的时间字段代表**结束时间**，标为 `ENDED`，默认为现在，因为常见情况是"刚跑完就记"。保存时 `startTime = 结束时间 − duration`。补记前几天的，就改结束时间。
- 导出时，开始和结束时间都写进文件，结束时间按上面的规则算出。

**注意：** 现在所有读取 `workout_history` 的地方都假设每条记录都有 `logs`，加入有氧记录后必须跳过或兼容。目前已知有：`SessionDashboard` 里"上次成绩"的查找、`HistoryManager` 的日历和编辑、导出功能。

### 7.3 结束页（已通过草图确认）

**入口：** 训练页底部原有的完成按钮，文字照旧：练完了显示 `FINISH WORKOUT`，没练完显示 `FINISH NOW (INCOMPLETE)`。

**流程：**

```
FINISH → 结束页 → SAVE LOG → 写入 workout_history → 回到封面
              ├→ SKIP RATING → 写入（sessionRpe: null） → 回到封面
              └→ ← BACK TO SESSION → 回到训练页，什么都不写
```

- 按 FINISH **不写入任何数据**，只是记下 `endTime`，进入结束页。
- 删除原来"没练完"时弹出的原生 confirm。结束页上显示的 `SETS 14/16`，加上可以返回训练，已经起到了确认的作用。
- 结束页的状态要存进 `active_session`，比如加一个 `phase: 'active' | 'debrief'`。在结束页关掉 app 后重新打开，应该仍然停在结束页。
- **页面内容：**
  - 页眉：`>_ SESSION COMPLETE`、训练日名称、`计划名 · 日期 · 时间`
  - SUMMARY 三格：
    - TIME：分钟数，可以修改，用来处理忘了按结束的情况
    - SETS：完成组数 / 计划组数
    - VOLUME：Σ 重量×次数，单位吨
  - SESSION RPE：1–10 的方格，两行，每行 5 个，下面标注量表说明
  - LOAD：实时显示 `7 × 58 min = 406`
  - 主按钮：样式 C 的 `SAVE LOG`；下面是 `SKIP RATING · 稍后在历史里补`

### 7.4 有氧快速记录（已通过草图确认）

- **入口：** 只在 LOGS（历史）页顶部放一个 `+ CARDIO` 按钮。作者表示可能不常用，所以不放在封面上。
- **形式：** 从底部弹出的面板。字段：
  - 类型：RUN / BIKE / SWIM / ROW / OTHER 五个方格，单选
  - ENDED：结束的日期和时间，默认现在，可以改成前几天（规则见 §7.2）
  - MINUTES：分钟数
  - SESSION RPE：1–10
  - LOAD：实时计算
  - 主按钮：样式 C 的 `SAVE`
- **在日历上：** 有氧和力量用不同的标记区分。

### 7.5 封面改动（方案 A，已确认）

只改下面几处，其他一律不动：

- **顶部标签：** `PRTS::TERMINAL_V3` 改成 `WEEK <ISO 周数> · <月 日>`，例如 `WEEK 44 · OCT 28`。
- **左格：** 标题 `THIS WEEK`，数值 `N SESSIONS`，小字 `x STRENGTH · y CARDIO`。
- **右格：** 标题 `WEEK LOAD`，数值是本周负荷总和，小字 `LAST WEEK <上周负荷>`。
- **进度条：** 左边写 `STRENGTH`，右边写 `x/y`。x 是本周力量训练次数，y 是默认计划里训练日的数量（不含休息日）。没有默认计划时，开发者自行决定隐藏还是退化成只显示次数。
- **两个格子可以点击**，跳到 LOGS 页，月历上选中今天。不新增"周视图"，历史页本身就能看到每天的场次、RPE 和负荷。这一条是我（Claude）定的。
- 删除右上角 MODE_SELECT（§6.1）。
- 封面底部 `TO BACKUP: GO TO LOGS > TOOLS` 的提示，改成指向新的数据页（§7.6）。
- 一周从周一开始，用 ISO 周数。历史页的日历目前从周日开始，应该改成从周一开始，跟封面保持一致。这一条是我（Claude）定的。

### 7.6 AI 页改成数据页（已确认）

底部导航第四个标签，原来的"开发中"占位页改成"把数据打包给 AI"的地方，里面有三样：

1. **EXPORT FOR AI：** 导出一个专门方便分析的 JSON 文件：
   - 每场一条记录，包括 `type`、`activity`、计划名和训练日名
   - 开始和结束时间用**带时区的 ISO 8601**，如 `2026-10-28T18:42:00+08:00`，方便 AI 按时间对上佳明的记录
   - `durationMin`、`sessionRpe`、`load`（导出时算出）
   - 力量训练的每个动作、每一组：重量、次数、RPE、休息时间
2. **复制提示词：** 一段说明上面文件格式的文字，提示 AI 可以按时间跟佳明的导出数据对齐，复制到剪贴板。原来写了一半、没接上的 `PromptGenerator` / `UserProfile` 要不要重用，由开发者决定。
3. **BACKUP / RESTORE：** 从 LOGS > TOOLS 搬过来。跟 AI 导出分开，备份是原始数据的完整副本。文件名 `antigravity_backup_*` 是遗留名称，改成跟这个 app 相关的名字。恢复前用 app 自己的确认框。

导航标签的文字和图标是否从 `AI` 改成别的，由开发者决定，要求能让人看出这是"数据 / 导出"。

## 9. 讨论过但不做的事

- **佳明：** 2026 年 10 月，佳明开放了免费、不需要审批的个人 API，可以读取活动摘要、.FIT 文件和健康数据；只能读，不能写。但浏览器 app 要用它，需要一个中转服务器来保管 key 和处理跨域请求，这会破坏"简洁、离线"。作者决定暂时不做。以后如果要做，优先考虑：
  1. 导入 .FIT 文件，不需要联网。手表上开启"自我评估"后，FIT 的 session 消息里有 workout RPE 和 feel 字段。
  2. 用 Cloudflare Worker 做无状态中转。
- **手动录入有氧作为必经步骤：** 作者明确不希望增加额外的输入动作，所以有氧录入只是一个可选入口。

## 10. 验收方式

- `npm run build` 成功；`npx eslint src` 的错误数不超过 18。
- 在 375px 宽度下逐页检查（含弹窗和空状态），对照 §6.3 的规则：
  - 没有看不见的文字
  - 没有斜体标题和胶囊按钮
  - 没有原生对话框
  - 内容不贴边，不被 RESUME 胶囊或导航遮挡
- **迁移：** 用一份带旧格式记录的 localStorage 启动：记录 `duration: 0`、没有 `type`；`app_style` 是 `cyber`；`app_theme` 是深色主题。确认不崩溃、旧记录正常显示、风格正确。
- **流程：**
  - 训练 → FINISH → 返回训练 → FINISH → 在结束页刷新页面 → 仍在结束页 → SAVE LOG → 封面数字更新
  - 跳过打分 → 在历史里补打
  - 录入一笔有氧 → 封面次数和负荷更新
  - 导出给 AI → 检查文件中的时间带时区
- 封面跟改动前逐区域对比：除了 §7.5 列出的改动，没有其他变化，`#D0FD3E` 的元素颜色不变。
